## 1. 总览

| 里程碑 | 主题 | 对应需求 | 前置 | 出口标志 |
|---|---|---|---|---|
| **M1** | 地基与格子渲染 | F1 | 无 | 平板双方向下格子正确、锐利、自适应 |
| **M2** | 手写核心 | F2 · F3 · F4 | M1 | 能用笔/手指连续书写、可擦可撤、手掌不干扰 |
| **M3** | 页面、存储与导出 | F5 · F6 · F7 | M2 | 多页可管理、强杀不丢、能导出与往返备份 |
| **M4** | 描红字帖 | F8 | M1 · M3 | 两类字帖可选、底字对齐参考线 |
| **M5** | PWA、真机打磨与发布 | F9 · F10 | M2 · M3 · M4 | 可安装、离线全功能、真机矩阵通过 |

```
M1 ──> M2 ──> M3 ──┬──> M4 ──┐
                   │         ├──> M5
                   └─────────┘
```

**排期原则**

- 严格串行推进 M1→M2→M3，这三个里程碑是「不可并行」的核心链路：格子布局决定坐标系，坐标系决定笔迹存储，笔迹存储决定页面模型。
- M4 必须在 M3 之后，因为字帖页是页面模型的一种 `kind`，先有页面才能挂字帖。
- **每个里程碑结束即为可运行 Demo**，不允许出现「等全部做完才能看到效果」的阶段。

## 2. M1 · 地基与格子渲染

### 目标
在安卓平板上把「一张不滚动、不变形、线条锐利的格子纸」渲染出来，建立后续所有模块依赖的坐标系与布局契约。

### 关键工作项

- 工程脚手架：Vue 3 + Vite + TypeScript、ESLint/Prettier、路径别名、开发服务器局域网可访问（真机调试必需）
- 编辑器骨架：三层 canvas 容器 + 顶栏 + 底栏，`touch-action: none`、viewport 禁缩放
- `GridLayout` 纯函数：田字格与四线三格的自适应布局计算（正方形、整数格、居中留白）
- `GridRenderer`：田字格（外框 + 十字虚线）、四线三格（4 条线 + 基线加深 + 第 2 线虚线）
- DPR 处理：物理像素后备存储 + 半像素对齐，验证 DPR 1.5 / 2 / 2.625 / 3
- 横竖屏切换与 `ResizeObserver` 触发的重排
- 视觉基调：纸张底色、线条颜色常量表、`gridConfig.ts` 集中管理可调参数

### 交付物

| # | 交付物 | 形态 |
|---|---|---|
| D1.1 | 可运行工程 | `npm run dev` 局域网可访问，平板能打开 |
| D1.2 | 格子渲染页 | 可在两种格子间切换的调试页 |
| D1.3 | `GridLayout` 模块 | 纯函数 + 说明注释 |
| D1.4 | 真机截图集 | 横竖屏 × 8/11/13 寸，用于后续视觉回归对比 |
| D1.5 | 参数基线表 | 格数、边距、线宽、颜色初值 |

### 完成标准（DoD）

- 8/11/13 寸、横竖屏共 6 种组合下，格子均为正方形，**无半格、无跳动、无溢出**
- DPR 2 与 3 的机型上，1px 线条不发虚、不发粗，放大截图无灰边
- 页面不可滚动、不可缩放、无橡皮筋回弹
- 旋转后 `cols` 与 `rows` 重新计算且不出现布局抖动（连续旋转 10 次无异常）
- 空页面无任何 JS 报错、无控制台警告

### 验收方式

真机目视 + 截图对比（对照 D1.4）+ 控制台零报错。

### 出口风险

| 风险 | 应对 |
|---|---|
| 平板 DPR 非整数导致线条发虚 | 若半像素对齐仍不达标，退化为 `lineWidth = 1/dpr` 并复查 |
| 部分机型视口高度报错（键盘/手势条） | 优先用 `visualViewport` 或 `100dvh`，实测后固定方案 |

## 3. M2 · 手写核心

### 目标
实现「笔跟着手走」的书写体验，并解决儿童场景最致命的问题——手掌压屏产生乱线。

### 关键工作项

- `PointerInput`：Pointer Events 采集、`getCoalescedEvents` 补点、归一化坐标换算、单指跟踪
- `StrokePainter`：分段描边 + round cap/join、中点二次贝塞尔平滑
- `WidthModel`：速度 → 线宽（EMA 平滑）、压感探测与优先、无压感机型自动回退
- `RenderEngine`：三层编排、rAF 主循环、live 层增量绘制、抬笔提交到 ink 层
- 笔模式：`pointerType === 'pen'` 自动进入、非笔事件丢弃、UI 仍可手指点击、显式退出按钮 + 持续可见状态指示
- `UndoStack`：笔画级撤销/重做（30 步）、`rebuildInk()` 重放
- `EraseHitTest`：包围盒剪枝 + 点线距离，整笔删除
- 性能面板（`?perf=1`）：首笔延迟 P95、FPS、掉帧统计

### 交付物

| # | 交付物 | 形态 |
|---|---|---|
| D2.1 | 可书写编辑器 | 手指/笔均可写，笔画保留 |
| D2.2 | 笔模式 | 自动进入 + 手动退出 + 状态指示 |
| D2.3 | 撤销/重做/擦除 | 工具栏三按钮 |
| D2.4 | 性能面板 | 开发模式开关 |
| D2.5 | 参数调优记录 | 速度阈值、线宽上下限、平滑系数的最优值 |

### 完成标准（DoD）

- 手指落点与笔迹起点偏差 ≤ 2 CSS px（横竖屏各测 20 次）
- 快速连写 100 次无断线、无折角、无「提前断尾」
- 慢写明显粗、快写明显细；主动笔下压感生效；无压感设备不出现死线宽
- 首次用笔后，手掌/手指压屏 10 次**零笔迹**；同时 UI 按钮仍可手指点击
- 撤销 30 步可逐级回退；新增操作后重做失效；800 笔页面撤销重建 ≤ 150ms
- 擦除点中即删整笔、不误删相邻笔、可撤销恢复
- 连续书写 60 秒：平均 FPS ≥ 55，掉帧占比 < 3%，首笔延迟 P95 ≤ 32ms

### 验收方式

真机实测（至少 1 台中端 + 1 台低端）+ 性能面板采样 200 次 + 目视检查。

### 出口风险

| 风险 | 应对 |
|---|---|
| 低端机达不到 55 FPS | 一级降级：关闭中点贝塞尔改用直线段；二级降级：降低采样上限至 800 点 |
| 笔模误判（把手指当笔 / 把笔当手指） | 记录真实设备 `pointerType` 日志，按机型加白名单兜底 |
| 压感机型表现参差 | 压感只做「增强」不做「必需」，速度模型始终作为基础路径 |

> **这是全项目风险最高的里程碑**。若 M2 的跟手性不达标，后续所有功能都失去意义，因此出口标准不做任何妥协，宁可延长 M2 也不带入 M3。

## 4. M3 · 页面、存储与导出

### 目标
让作品「留得住、找得到、带得走」：多页管理 + 本地持久化 + 导出与备份往返。

### 关键工作项

- 数据层：`db.ts`（schema/迁移）、`PageRepository`（元数据与笔迹分表）
- `SaveQueue`：抬笔 debounce + 上限节流 + 强制落盘时机（切页/隐藏/卸载/导出前）
- 缩略图生成（30s 节流、WebP）
- 页管理 UI：页列表（缩略图网格）、新建页弹层、翻页箭头、删除二次确认
- 首次启动逻辑：无数据时自动建一页空白田字格并直入书写区；恢复上次所在页
- 导出单页 PNG（`OffscreenCanvas` + `toBlob`，2x，长边 ≤ 2400px）
- 备份导出 JSON + 导入校验（格式/版本/逐页容错/事务回滚/新 id 追加）
- 存储可靠性：`navigator.storage.persist()`、降级内存模式 + 显式告警横幅
- 撤销栈与页面切换的联动（切页丢弃栈、切换前提交未完成笔画）

### 交付物

| # | 交付物 | 形态 |
|---|---|---|
| D3.1 | 多页编辑器 | 新建/切换/删除/列表全通 |
| D3.2 | 持久化层 | `PageRepository` + `SaveQueue` |
| D3.3 | 导出 PNG | 单页图片，无 UI |
| D3.4 | 备份导出/导入 | JSON 往返完整 |
| D3.5 | 崩溃恢复验证报告 | 强杀测试记录 |

### 完成标准（DoD）

- 新建页继承当前格子类型与列数；翻页不丢笔迹、不串页
- 删除末页后自动补一页空白，不出现空本子
- 落笔后 3 秒内切后台 / 强杀进程，重开内容与最后一次落盘一致（连续 10 次零丢失）
- 关闭页面再打开，自动回到上次所在页
- 200 页的页列表打开 ≤ 500ms
- 导出 PNG：含格子与笔迹、无工具栏、长边 ≤ 2400px、文件名含日期时间；导出期间书写交互不卡顿超过 100ms
- 备份往返：导出 → 清空 → 导入，页数、笔迹、格子类型、字帖信息完全一致
- 导入非法/高版本 JSON：明确报错且**零写入**
- 存储不可用时进入内存模式并有可见告警，不静默丢数据

### 验收方式

强杀测试脚本（含计时）+ 往返比对（页数与轨迹点数逐项核对）+ 200 页压测。

### 出口风险

| 风险 | 应对 |
|---|---|
| 结构化克隆大数组导致卡顿 | 笔迹点用扁平 `number[]`；必要时分片提交 |
| 系统清理 IndexedDB | 已做 `persist()` + 备份提醒，写入「异常恢复」用例固化 |
| 缩略图生成拖慢保存 | 30s 节流 + `OffscreenCanvas` 异步；必要时降到 15s 一次 |

## 5. M4 · 描红字帖

### 目标
把「格子纸」升级成「字帖」：两类字帖可选、底字用楷体、与参考线视觉对齐。

### 关键工作项

- 字库 JSON 结构落地与三份内置数据：拼音字母表（26 小写）、拼音声调（a/o/e 四声）、汉字常用字（约 60 字）
- 字体流水线：LXGW WenKai 子集化（含声调字符）→ woff2 → `FontFace` 异步加载 → 失败降级
- `CopybookRenderer`：demo/trace 两级透明度、汉字居中 78%、拼音基线对齐第 3 线
- `PINYIN_FONT_SCALE` 校准（以 a/o/e 为基准，误差 ≤ 2px）
- 行内结构：1 示范 + 2 描红 + 其余空白；超出单页自动拆分为连续多页
- 字帖选择器 UI：卡片列表 + 字形预览 + 字库名与字数
- 字帖页与空白页的混合排布（同一本子内可共存）
- 视觉回归截图：三类字帖页 × 横竖屏

### 交付物

| # | 交付物 | 形态 |
|---|---|---|
| D4.1 | 字库 JSON × 3 | `src/lib/copybooks/` |
| D4.2 | 楷体子集字体 | `public/fonts/wenkai-subset.woff2` |
| D4.3 | 字帖页渲染 | demo/trace/blank 三种角色 |
| D4.4 | 字帖选择器 | 卡片列表 + 预览 |
| D4.5 | 校准记录 | `PINYIN_FONT_SCALE` 取值依据与验证截图 |

### 完成标准（DoD）

- 拼音字帖：26 字母全部可选；底字坐在第 3 线上，`a/o/e` 误差 ≤ 2px（放大 4 倍目视）
- 汉字字帖：底字居中、四周留白均匀、不触边、不超格
- 每行严格 1 demo + 2 trace + 其余 blank，横向间距一致
- 字库条目超出单页容量时自动拆成连续多页，顺序不断
- 字体子集 ≤ 600KB，加载不阻塞首屏；断网时字帖正常显示（不出现豆腐块，含声调字符）
- 字帖页可正常书写、擦除、撤销、导出
- 新增一个自定义字库只需新增 JSON 文件、不改代码

### 验收方式

4 倍放大截图与参考线比对 + 断网加载验证 + 新增字库的「零代码接入」演练。

### 出口风险

| 风险 | 应对 |
|---|---|
| 汉字字库内容不确定（PRD Q2） | 先用占位常用字打通链路，内容确认后仅替换 JSON |
| 字体授权或体积不达标 | 备选：更小字重的楷体子集 / 按分组二次拆分按需加载 |
| 对齐常量在不同字号下漂移 | 校准常量按 `u` 线性缩放推导，而非固定像素 |

## 6. M5 · PWA、真机打磨与发布

### 目标
把网页变成「可以装到桌面、断网能用」的 App，并通过真机验收矩阵，达到可交付状态。

### 关键工作项

- PWA 接入：`vite-plugin-pwa`、Manifest（standalone/图标含 maskable）、SW 预缓存（含字体与字库 JSON）
- 安装引导：`beforeinstallprompt` 捕获、非书写区展示、忽略后 7 天不再弹、已安装时隐藏
- 离线验证：飞行模式冷启动、全功能可用
- 版本更新策略：`autoUpdate` + 应用内「有新版本」提示（禁止书写中自动刷新）
- 设置与偏好（F10）：笔宽三档、更多面板（导出/导入/退出笔模式/关于）
- 性能收口：按 TECH §13 清单逐项核对，形成实测数据表
- 真机验收矩阵全量执行（尺寸 / 方向 / 输入 / 系统 / 网络状态）
- 缺陷收敛、文案与图标定稿、部署上线（HTTPS 静态托管）

### 交付物

| # | 交付物 | 形态 |
|---|---|---|
| D5.1 | 可安装 PWA | 线上地址 + 安装流程录屏 |
| D5.2 | 设置面板 | 笔宽 + 更多面板 |
| D5.3 | 验收报告 | PRD §7 全部 A1–A18 逐项结论 |
| D5.4 | 性能实测表 | 首笔延迟 P95 / FPS / 冷启动 / 列表加载 |
| D5.5 | 发布版本 | 版本号 + 变更说明 + 回滚方式 |

### 完成标准（DoD）

- PRD §7.1 的 A1–A18 **全部通过**，无 P0/P1 缺陷遗留
- PRD §7.2 性能指标全部达标（基准机型）
- PRD §7.3 真机矩阵全部覆盖并留有记录
- Chrome 出现安装入口；安装后独立窗口、无地址栏；已安装不再弹安装提示
- 飞行模式冷启动可进入，书写/翻页/字帖/导出全部可用
- 首屏资源（gzip）≤ 500KB；全量预缓存 ≤ 3MB
- 无控制台报错、无第三方网络请求（隐私要求）

### 验收方式

真机矩阵逐项执行 + 儿童可用性走查（3 名 5–8 岁）+ 断网演练 + 冷启动计时。

### 出口风险

| 风险 | 应对 |
|---|---|
| 缺 HTTPS 部署地址导致无法验证安装 | 提前在 M3 期间准备好静态托管（PRD Q4 需尽早确认） |
| 儿童可用性走查不通过 | 预留一轮 UI 简化迭代：减少按钮、放大图标、去掉文字依赖 |
| SW 缓存导致旧版本残留 | 版本号 + `autoUpdate` + 显式「点此刷新」入口 |

## 7. 里程碑门禁规则

每个里程碑结束时执行一次门禁评审，**未通过不带入下一阶段**：

| 检查项 | 要求 |
|---|---|
| 功能完整性 | 该里程碑 DoD 全部条目有明确结论（通过/不通过） |
| 可运行性 | 能真机跑通主流程，不是半成品分支 |
| 数据安全 | 不存在「可能导致已有数据损坏」的已知缺陷 |
| 技术债登记 | 遗留问题写入待办并标注影响范围，不允许口头遗留 |
| 文档同步 | PRD/TECH 如有变更需同步更新 |

## 10. 变更管理

- **需求变更**：只接受写入 PRD §3 版本规划（V1.1 及以后）的排期，V1.0 范围内不插队。
- **方案变更**：涉及架构分层、坐标系、存储 schema 的变更必须同步更新 TECH 文档并重新评估当前里程碑。
- **验收口径变更**：性能指标只允许在基准机型确认后调整一次，调整后固化，不再反复。
